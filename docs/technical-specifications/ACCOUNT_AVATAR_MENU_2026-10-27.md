# Меню аватарки, приватность и смена аккаунта – 27.10.2026

## Видимость по роли

| Роль в Supabase | Кнопки меню | Видимость списка пользователей |
|---|---|---|
| participant | Профиль, Настройки, Выйти | Нет доступа к управлению |
| moderator | Профиль, Настройки, Сменить аккаунт, Выйти | Нет доступа к управлению, состав администрации не раскрывается |
| owner | Профиль, Настройки, Управление, Сменить аккаунт, Выйти | Через защищенную серверную функцию с MFA; Тень исключена из обычного списка |
| shadow | Профиль, Настройки, Управление, Сменить аккаунт, Выйти | Через защищенную серверную функцию с MFA; изменения фиксируются в журнале |

Вкладка "Управление" открывает `manage-users.html`. На сервере `manage-user-roles` независимо проверяет собственную роль пользователя, токен, AAL2, запрещает выдачу ролей обычным участникам и модераторам, скрывает shadow в списке пользователей.

## Смена аккаунта

Кнопка для администрации завершает текущий сеанс после подтверждения, затем открывает форму входа через одноразовый код. Она **не** дает мгновенно входить за любого из трех пользователей по административной роли и **не** сохраняет чужие сеансы. Можно отдельно войти в любые свои три аккаунта, но каждый переход требует повторной авторизации. Роль `shadow` не показывается в каталоге других пользователей.

## Аватар и личная анкета

Предыдущий код обращался к общим ключам `psy-avatar-demo` и `psy-profile-demo`. Теперь `site-account-identity.js` после верификации аккаунта использует для локальной анкеты и фотографии ключи `psy-profile-v2:<user_id>` и `psy-avatar-v2:<user_id>`. Прежнее общее фото не присваивается автоматически новому аккаунту. Оно остается в браузере только как неиспользуемая устаревшая запись; при желании пользователь загружает фото заново в своей учетной записи.

Изображение и анкета пока сохраняются локально на устройстве, а не синхронизируются между устройствами. Роль, вход и телефон используют Supabase, не демоданные браузера.

## Контакты

Профиль изначально показывает "Электронная почта скрыта" с кнопкой просмотра своей почты. Поле телефона по умолчанию замаскировано и имеет кнопку показа. Номер по-прежнему сохраняется только в `psy_user_profiles`, где RLS ограничивает чтение и изменение по `auth.uid() = user_id`. Модераторы и участники не могут читать телефоны других через Data API.

## Техническая приемка

- Двенадцать основных страниц с шапкой и аватаркой подключают новые JS/CSS, идентификатор аккаунта проверяется по Supabase.
- Проверены сборка JS, загрузочный порядок, раздельные localStorage ключи для двух тестовых учетных записей, пять вариантов меню, подтверждение перед сменой аккаунта, серверное исключение shadow из списка.
- Прежний глобальный `psy-avatar-demo` больше не читается в шапке и редакторе профиля.
- Не проверено на работающем Render в браузере (доступ к подходящей рабочей области Render не подтвержден). Коммиты в GitHub не гарантируют публикацию.

## Основные файлы

`site-account-identity.js`, `site-avatar-menu.js`, `site-avatar-menu.css`, `site-chrome.js`, `site-account.js`, `site-account-access.js`, `profile-phone.js`, `manage-users.js`, HTML основных страниц и карточек методик.

## Невыполненная часть полного переключателя

Три **одновременно сохраненных** независимых сеанса с переключением без подтверждения не реализованы. Такое поведение требует дополнительного проектирования изолированного хранилища сеансов, сохранения MFA, логов и защиты от перехода в чужой аккаунт. Сейчас переход возможен только через новый вход, что безопаснее.
