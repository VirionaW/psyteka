# ТЗ 11. Единый реестр методик и готовности

**Редакция 1.0, 26.10.2026.** Реестр – подтвержденный учет, а не автоматически правдивый список.

## Инвентаризация
Сверить актуальный каталог и файлы по уникальным методикам. Исторические 90 файлов **не доказывают** наличие 90 уникальных методик. Проверить дубли, адаптации и версии. Один ID – одна основная запись; связанные руководства, бланки, стимулы, обработка, изображение и задачи указывают на нее.

## Поля
ID, название, автор и его статус проверки, адаптация, версия, основная категория и тип, возраст, изображение, портфолио, руководство, бланк, стимулы, обработка, публикация, общий статус, ответственный чат, последняя версия и дата проверки. Дополнительные таблицы: задачи, методические источники, проверки, история изменений.

## Состояния
**Не начато / В работе / Подготовлено / На проверке / Проверено / Ошибка / Заблокировано / Не требуется.** Не путать «Подготовлено» с «Проверено» или «Не требуется» с «Отсутствует». Готовность алгоритма разработки **не** равна зеленому статусу заполнения результатов конкретного обследования.

## Учет и выбор задач
Смотреть актуальный реестр перед назначением. Отмечать исполнителя и область файлов; после работы фиксировать фактический коммит, тесты, ограничения и состояние публикации. Если реестр недоступен, честно сообщить и не притворяться, что он обновлен. Новые партии методик выбирать из свободных, без дублирования соседних чатов.

## Сводки
Список без изображений с подтвержденным автором и отдельный список с неподтвержденным автором; методы с непроверенными ключами и обработкой; методы без необходимых стимулов; активные и заблокированные задачи; реально проверенные методы. Не заполнять неизвестные поля вымышленными значениями.

## Реализация
Приложенные CSV – **пустые шаблоны**, не результаты инвентаризации. При ведении в GitHub избегать потери строк при параллельной работе. Персональные данные обследуемых в реестр разработки не вносить.
