# Психотека: регистрация и личный аккаунт

Статус: **в GitHub подготовлена отключенная страница входа**. На 26.10.2026 в Supabase у организации Psyteka нет проектов. Поэтому реальная регистрация, отправка писем, учетные записи и синхронизация не запущены. Не добавлять ссылку на регистрацию в публичные меню до готовности.

## Что подготовлено

- `register.html`, `registration.css`, `registration.js` – самостоятельная адаптивная страница регистрации и входа по электронной почте.
- `auth-config.js` – отключенная конфигурация. После создания Supabase-проекта заполнить **только** URL проекта и **publishable key**; никогда не размещать секретный ключ или service_role в публичном коде.
- Текущий демо-профиль на `profile.html` и тестовый код доступа к библиотеке не изменены. Это отдельные механизмы, синхронизации между ними пока нет.

## Следующие обязательные шаги

1. Получить подтверждение владельца, что новый проект можно создать именно в организации `Psyteka`, и согласовать стоимость (узнать через инструмент Supabase get_cost).
2. Создать проект в подходящем регионе с учетом хранения данных и выбора владельца. Не обещать размещение только в РФ.
3. Настроить Auth Site URL на `https://psyteka.onrender.com` и разрешить redirect URL `https://psyteka.onrender.com/register.html`. Подтвердить, что email-провайдер включен, при необходимости изменить email-шаблон для OTP с `{{ .Token }}`. По умолчанию Supabase отправляет magic link.
4. Создать `public.profiles`, `public.favorite_methods`, `public.method_folders` и таблицу связей для папок. Включить RLS на каждой таблице и политики по `auth.uid() = user_id`, запретить произвольный перенос владельца при UPDATE. В публичных схемах не использовать привилегированные definer-функции.
5. Подключить `auth-config.js` с URL и publishable key без секретов. Проверить регистрацию, вход, повторный вход на другом устройстве, выход, RLS с двумя независимыми тестовыми аккаунтами, удаление данных.
6. Только после полной проверки заменить демо-профиль на реальную сессию и включить вход в меню сайта. Не переносить личную информацию из localStorage без явного действия пользователя.
7. Не хранить результаты обследования детей, ФИО детей и другие чувствительные сведения в таблицах избранного.
