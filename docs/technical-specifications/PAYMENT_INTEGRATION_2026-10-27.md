# Психотека – безопасная подготовка месячных платежей (27.10.2026)

## Российский продавец – уточнение от 27.10.2026

Страна приема платежей подтверждена: **Россия**. Следующий обязательный выбор – правовой статус продавца: самозанятая (НПД), ИП или ООО. Не включать боевую оплату, пока он не указан и нет договора с провайдером.

- **НПД:** ЮKassa принимает самозанятых (паспорт, ИНН и идентифицированный ЮMoney), но с **29.12.2025** прекратила сервис автоматического формирования чеков для самозанятых. Чеки в «Мой налог» потребуется формировать/направлять самостоятельно или отдельно выбрать другого провайдера с действующей автоматизацией. Альтернатива – Robokassa «Робочеки СМЗ», заявляет автоматическое формирование чеков и отправку покупателю. Проверить условия и договор на момент регистрации.
- **ИП/ООО:** подготовленная ЮKassa подходит при заключении договора; нужен законный способ фискализации по 54-ФЗ, например онлайн-касса или доступный сервис ЮKassa «Чеки от ЮKassa».
- При подключении ни номер своей карты, ни ключи магазина нельзя размещать в GitHub, коде страницы или чате. Реквизиты счета для выплат сообщаются исключительно провайдеру внутри его защищенного кабинета.
- Для Психотеки с методиками разных авторов до продажи доступа нужно проверить лицензии и право коммерческого распространения материалов. Для НПД отдельно проверять квалификацию дохода: закон ограничивает перепродажу чужих товаров/имущественных прав.

Проверенные официальные сведения: [условия для самозанятых ЮKassa](https://yookassa.ru/docs/support/payments/conditions), [подтверждение прекращения автоматических чеков 29.12.2025](https://yookassa.ru/developers/using-api/changelog), [ФНС: НПД](https://npd.nalog.ru/), [ФНС о чеках для самозанятых, 26.08.2026](https://www.nalog.gov.ru/rn53/news/activities_fts/16643640/), [Robokassa для самозанятых](https://robokassa.com/solutions/business/samozanyatye/).

## Пользовательское решение
Оплату за цифровые методические материалы **не принимаем переводом на опубликованную личную карту**. Используем платежную форму провайдера (для рублей подготовлен адаптер ЮKassa), с договором мерчанта, верификацией владельца, документами для покупателей и реквизитами для выплат в кабинете провайдера.

### Подписки
- «Знакомство»: 0 ₽, 48 часов, однократно.
- «Специалист»: предварительно 390 ₽, **разовая оплата на 1 календарный месяц** (без автосписаний). Подготовлена техническая интеграция.
- «Организация»: предварительно 890 ₽, 1 месяц, **оплата недоступна, пока не готовы кабинеты и управление местами**.
- Годового «Специалист+» нет.

Цена предварительна, оплату нельзя включить без отдельного утверждения владельца, подключенных чеков и готовности защищенного контента. Обязательные документы для покупателя и кассовые обязанности зависят от страны продавца и правового статуса (самозанятый / ИП / компания).

## Реализованное техническое основание

**Сервер:** Supabase Edge Function `psy-payment-checkout` (развернута, однако сама продажа отключена).

- `availability` возвращает `enabled=false`, пока не выполнены все условия запуска.
- `start` доступен только аутентифицированному владельцу аккаунта с подтвержденной почтой, без привилегированной роли, и только для `specialist`.
- Цена **задается сервером**: 39000 копеек, RUB, никогда не берется из формы браузера.
- Создание платежа через API ЮKassa /v3/payments: Basic Auth с серверными ключами, `Idempotence-Key`, сценарий redirect на защищенную форму. Номер карты и CVC на Психотеку не передаются.
- При `return_url` нет автоматической выдачи доступа. `check` запрашивает статус платежа **напрямую у ЮKassa** и только при `succeeded + paid=true + test=false + совпадение суммы, валюты и идентификатора` активирует оплаченный месяц.
- Встроена обработка уведомлений ЮKassa: HTTP callback с `type=notification` повторно проверяет соответствующий платеж по API магазина. Само тело уведомления не считается подтверждением оплаты.
- Многократная обработка одного успешного заказа не добавляет оплаченных месяцев. Срок продлевается от более поздней даты: сейчас или конца уже активной подписки.
- Продажи выключены по умолчанию, обработчик не принимает банковские реквизиты и не может выдавать оплату по сообщению «успешно» в браузере.

**База Supabase:** `psy_payment_orders`, `psy_paid_access`, миграция `20261027070058` и серверная функция `psy_settle_payment`.
- RLS разрешает клиенту **только просмотр своих заказов и срока**.
- Анонимный/обычный клиент не может INSERT/UPDATE оплаченных заказов и доступа.
- `psy_settle_payment` доступна `service_role`, не `authenticated` и не `anon`.
- Форма сайта и вход в библиотеку читают `psy_paid_access`; пробный таймер не показывается при активной оплаченной подписке.

**Интерфейс:** `subscriptions.html`, `site-payment.js`, `site-subscriptions.js`, `site-subscriptions.css`, `site-access.js`, `site-library-entry.js`, `site-library-timer.js`. На странице описание последовательности платежа и статус оплаты, кнопки включаются только по ответу сервера.

## Что обязательно сделать ДО приема реальных денег

1. Определить **страну регистрации продавца** и правовой статус: РФ/самозанятость/ИП/ООО или другая юрисдикция. ЮKassa подключается при соответствии требованиям провайдера; если продавец зарегистрирован в Германии, этот адаптер может оказаться неподходящим и потребуется иной провайдер с другой валютой.
2. Создать и подтвердить мерчант-аккаунт **у провайдера**, пройти KYC и указать свои платежные реквизиты для выплат **только там**, не на публичном сайте и не в ChatGPT.
3. Утвердить 390 ₽ и 890 ₽ либо заменить на выбранные цены. Рассчитать комиссии и налоги.
4. Опубликовать сведения о продавце, оферту и порядок возвратов, сроки цифрового доступа, политику конфиденциальности, способ поддержки. Выполнить требования по чековой/фискальной отчетности (для РФ: 54-ФЗ или режим НПД по применимости).
5. Проверить, кто может открывать **сами методические файлы**. Сейчас сайт статический, ссылки доступны непосредственно – клиентская проверка входа не защищает контент. Перед включением платного доступа необходимо перенести платные материалы в приватное хранилище и выдавать краткосрочные подписанные ссылки через сервер после проверки `psy_paid_access` / пробного периода.
6. Подготовить обработку возвратов, отмен/оспариваний, повторов и уведомлений провайдера, тесты и мониторинг. Текущее развертывание **не должно** принимать реальные деньги до устранения этих ограничений.
7. После выполнения и реальной проверки в тестовом/боевом режиме настройте **секреты Supabase Edge Functions** `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY` в панели Supabase (не в GitHub/HTML). Для запуска продаж отдельно нужны подтвержденные флаги:
   `PSY_PAYMENTS_ENABLED=true`
   `PSY_PRICES_APPROVED=true`
   `PSY_FISCALIZATION_READY=true`
   `PSY_PRIVATE_CONTENT_READY=true`
   `PSY_YOOKASSA_LIVE_CONFIRMED=true`
   `PSY_REFUND_PROCESS_READY=true`
   Пока хотя бы один отсутствует, **checkout остается заблокированным**. Эти флаги являются подтверждением завершения работ, а не заменой самой реализации пунктов 4-6.
8. Если используется ЮKassa, настройте `payment.succeeded` и `payment.canceled` на callback:
   `https://uwouubzabqpuujuovala.supabase.co/functions/v1/psy-payment-checkout`.
   Обработчик повторно запрашивает платеж у провайдера и не доверяет статусу из уведомления.
