# Психотека – окно входа и пробные 48 часов

Редакция: 26.10.2026.

## Пользовательский сценарий

1. Главная страница открывается без кода тестера.
2. Нажатие на ссылку библиотеки, раздел или пример методического комплекта вызывает модальное окно входа.
3. При включенной регистрации: почта → письмо/код → выбор пробного плана → библиотека.
4. Бесплатный план действует **48 часов с момента добровольного начала**. Карта не требуется, списания и автопродление отсутствуют.
5. Часы отображаются в окне и в верхней части библиотеки, основаны на `expires_at` Supabase. Владелец и модератор не расходуют пробный период.
6. После истечения пробного срока новые переходы через окно ведут к сообщению об окончании; реальные платные подписки еще не подключены.

## Временный режим до запуска регистрации

`auth-config.js.registrationEnabled = false` – так как доставку почты для обычных пользователей через SMTP и Site URL/redirect URL еще нужно настроить.

Окно показывает честное сообщение о подготовке и отдельное действие «Посмотреть тестовую библиотеку». При нажатии действует только **демонстрационное** разрешение на текущую браузерную сессию. **Оно не считается подпиской, не запускает таймер, не создает аккаунт и не гарантирует сохранность данных.** После рабочего SMTP эту ветку отключают.

Прежний экран с кодом тестера убран из главной; старый фиксированный код доступа не проверяется.

## Безопасность и ограничения

- Таблица `psy_trial_access`, миграция [20261026105421](../../supabase/migrations/20261026105421_psyteka_two_day_single_use_trial.sql).
- RLS SELECT/INSERT только для собственного UUID; INSERT только колонки `user_id`, без прав на клиентскую запись `started_at` или `expires_at`; UPDATE/DELETE не предоставлены. Уникальный `user_id` исключает повторный запуск. Выполненные SQL-проверки подтверждают запреты.
- Таймер в браузере не является доказательством доступа: часы пользователя и JavaScript могут быть изменены. Истина – Supabase.
- **ВАЖНО:** статическая библиотека Render и публичные файлы GitHub/Render пока доступны напрямую через URL. Переадресация и модальное окно **не защищают** материалы от скачивания или обхода. До запуска платных планов необходимо перенести защищаемые файлы в PRIVATE Storage или backend, проверяющий JWT и `expires_at` на сервере при каждой выдаче. Не продавать доступ, полагаясь только на CSS/JS.
- Статическая защита страницы не заменяет SMTP rate limits, CAPTCHA, MFA владельца или серверную авторизацию.

## Для полноценного включения

1. Supabase Authentication → URL Configuration: Site URL `https://psyteka.onrender.com`, разрешенный Redirect URL **`https://psyteka.onrender.com/index.html?home=1&entry=1`**. Старый `register.html` – дополнительная страница, а новый сценарий используется на главной.
2. Подключить и проверить SMTP. Встроенная почта Supabase предназначена для ограниченной тестовой отправки адресатам команды проекта.
3. На тестовом аккаунте пройти регистрацию, подтверждение, однократную активацию пробных 48 часов, таймер и истечение. Отдельно проверить отказ в изменении сроков через REST.
4. Только после этой проверки включить `registrationEnabled: true`, отключив демонстрационный обход, и опубликовать.
5. Перед реальными продажами: серверная выдача файлов, платежный провайдер, пользовательские условия, конфиденциальность и отмена/возвраты.
