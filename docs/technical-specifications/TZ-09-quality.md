# ТЗ 09. Контроль качества и приемка

**Редакция 1.0, 26.10.2026.** Завершение работы означает проверенный результат, а не наличие коммита.

## Пять проверок
1. **Содержание:** название, автор, версия, инструкция, стимулы, ключ, интерпретация.
2. **Функции:** карточка, вкладки, кнопки, формы, правильное открытие и закрытие.
3. **Комплект:** согласованность руководства, бланка, стимулов и обработки.
4. **Регрессия:** соседние методики и общие компоненты после правок.
5. **Публикация:** только если входит в задачу – фактическая доступность нужной версии на рабочем сайте.

## Критические сценарии
- Кнопка обработки справа; без лишней кнопки закрытия и дублирующих ссылок.
- Пустой/частичный ввод – оранжевый; корректный полный и рассчитанный – зеленый; удаление обязательного значения снова оранжевый.
- Независимые контрольные примеры для ключей, прямого/обратного кодирования, формул, граничных норм; пусто ≠ ноль.
- «Простые аналогии»: проверка ключа и расчета отдельно; таблицы Шульте: времена, поля и подтвержденные формулы.
- Руководство «Без бланка» / «С бланком» не содержит самостоятельных стимулов; бланк не содержит ключа.
- Печать А4 без обрезки, пустых листов и элементов сайта.
- Карточки одного размера; группы меню корректно сворачиваются; компьютер, планшет, телефон; светлая/темная тема, если есть.
- Защита персональных данных и синтетические тестовые обследования.

## Статусы
«Реализовано» ≠ «Проверено локально» ≠ «Объединено» ≠ «Опубликовано» ≠ «Проверено на сайте». Для каждого утверждения иметь фактическое основание. Ошибки расчетов и утечки данных блокируют приемку. При блокировке источников не выдумывать данные.

## Отчет
Методика/задача, сделано, измененные файлы, методический источник, проведенные тесты, результат проверки, проверка других компонентов, публикация и ограничения. Не писать «все проверено», если браузер или печатный просмотр не открывались.
