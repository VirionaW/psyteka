# Решение о размещении, 9 ноября 2026

## Важно: не покупать управляемую БД только ради переноса Supabase

Владелец настроил Timeweb Managed PostgreSQL 17, Москва, 1 CPU, 1 ГБ RAM,
8 ГБ NVMe, бэкап и приватная сеть (в интерфейсе ориентир ~1 248 ₽/мес.).
**База еще не заказана.**

Это обычная управляемая СУБД, **не** полноценный Supabase.
Timeweb прямо пишет, что root-пользователь управляемой БД недоступен:
https://timeweb.cloud/docs/dbaas/dbaas-manage/users

Для полного сохранения Supabase Auth (auth.users, identities, MFA), RLS,
служебных ролей, extensions и PostgREST недостаточно просто импортировать SQL
в обычную БД: нужны привилегии, нужные расширения и серверы Auth/API.
Потребуется существенно больше работы и рисков, если разрабатывать
самостоятельную регистрацию на Express. Не смешивать такую разработку с
переносом реальных обследований детей.

## Рекомендация для тестового контура

**Временная российская self-hosted Supabase на одном VPS с Docker**, а не
отдельные Managed Postgres + Express.

- PostgreSQL, Auth, PostgREST и необходимые части Supabase должны оставаться
  совместимыми с имеющимся браузерным supabase-js.
- Для теста только на синтетических данных: минимум 2 vCPU / 4 ГБ RAM /
  40 ГБ SSD согласно текущей документации Supabase. Рекомендовано
  4 vCPU / 8 ГБ / 80 ГБ. Ресурсы меньше минимума – не подтверждены.
- Timeweb (регион РФ) либо другой российский VPS; проверить стоимость
  до покупки. Использовать официальный Docker Compose Supabase, без
  публичного порта PostgreSQL.
- Настроить SMTP-отправителя на metolaria.ru (SPF, DKIM, DMARC) и испытать
  OTP на Mail.ru/Яндекс/Gmail без публикации секретов.
- Только тестовые аккаунты и выдуманные данные до проверки импортирования,
  сохранности UUID, RLS и двухфакторной защиты.
- Полный перенос пользователей и данных выполнить позднее по официальному
  `supabase db dump` + restore, предварительно проверив поддержку версий.
- После переноса старые сессии потребуют нового входа; **учетные записи
  сохраняются**. MFA требует отдельной приемки.

## Если принципиально выбирать Managed PostgreSQL + Express

Это другая архитектура, не мгновенный перенос Supabase. Придется спроектировать
и протестировать новую систему Auth, выдачи токенов, контроля доступа,
все API для обследований, Edge Functions и импорт старых UUID/ролей.
Ни одно серверное приложение с этими функциями в рабочем состоянии сейчас
не существует; не оплачивать базу с расчетом, что все заработает автоматически.
Начинать с архитектурного прототипа и испытания синтетических данных.

## До покупки

1. Не отключать действующий Supabase.
2. Не вводить учетные данные/секреты в GitHub или чат.
3. Сравнить фактическую стоимость российского VPS (2 vCPU/4 GB/40 GB)
   с суммой Managed PostgreSQL + App Platform.
4. Выбрать минимальную установку для теста, но не ниже официальных
   ограничений нужных контейнеров.
5. Проверить итоговый стек и требования безопасности перед заказом.
