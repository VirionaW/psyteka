# Метолария: перенос всей инфраструктуры в Россию

Статус: подготовка, **переключение не выполнено**. Текущий сайт и Supabase продолжают работать.

## Цель
Оставить `https://metolaria.ru` на действующем российском App Platform, но заменить облачный Supabase европейского региона полностью самостоятельной установкой **Supabase Docker** на VPS, физически размещенном в России.

Все операции с реальными личными данными выполняются на защищенном сервере, не через общедоступный GitHub, чаты или логи.

## Доказанная исходная конфигурация (09.11.2026)
- Управляемый Supabase: PostgreSQL 17, регион eu-central-1.
- 4 записи в auth.users, 4 identities, 2 подтвержденных MFA-фактора.
- 22 записи psy_saved_assessments, 10 psy_assessment_drafts, 2 psy_user_collections.
- 0 объектов storage.objects.
- 2 Edge Functions: manage-user-roles (JWT обязателен), psy-payment-checkout.
- В PostgreSQL включены pgcrypto, uuid-ossp, supabase_vault, pg_stat_statements, plpgsql.
- Более подробные контрольные значения **заново снять перед финальным переключением**, поскольку обследования продолжают добавляться.

## Ограничения до начала
- Не запускать и не оплачивать приложение `metolaria-auth-proxy` как замену базы. Посредник оставляет персональные данные в ЕС.
- Не менять `auth-config.js` в рабочей ветке, не удалять учетные записи и не сбрасывать сессии.
- Не включать автодеплой изменений из этой ветки на основной сайт.
- Для полного Supabase рекомендуются 4 vCPU, 8 ГБ RAM, 80 ГБ SSD или больше.
- У App Platform контейнерная файловая система может пересоздаваться: база должна находиться на долговечном хранилище VPS, а не внутри обычного контейнера App Platform.
- Перед размещением персональных данных проверить договор обработки данных, российский регион и требования 152-ФЗ.

## Дорожная карта
1. Выбрать российский VPS (проверить фактическую локацию, 4 vCPU / 8 ГБ / 80 ГБ, IPv4, цену с резервным копированием). Выбранный тариф и подтверждение заказа зафиксировать отдельно.
2. Ubuntu 24.04 LTS, Docker Engine + Compose, сетевой экран, SSH-ключи, TLS, регулярные зашифрованные бэкапы с тестом восстановления.
3. Развернуть официальную self-hosted Supabase, согласовать версии Postgres (исходный PG17). Сгенерировать **новые** JWT, publishable/secret, dashboard, DB и другие секреты только в локальном `.env`. Не помещать секреты в GitHub.
4. Зафиксировать baseline перед экспортом, полностью выгрузить роли, схему и данные штатным `supabase db dump`; проверить, что переносит `auth.users`, `auth.identities`, MFA, RLS, триггеры и все таблицы `public`. Шифровать и хранить копию отдельно.
5. Восстановить в тестовом сервере по официальной инструкции. Самостоятельно развернуть обе Edge Functions. Проверить Vault и функции на наличие зависимостей от хостинга.
6. Почта: настроить SMTP с российским отправителем на домене metolaria.ru, проверить SPF, DKIM и DMARC. На тестовых адресах Gmail, Mail.ru и Яндекс Почта проверить отправку OTP, получение, попадание в спам и повторную отправку. Не считать Mail.ru заблокированным без журнала SMTP.
7. Вывести API только через HTTPS на российском домене `api.metolaria.ru`; ограничить доступ к Studio и PostgreSQL. Проверить RLS, API и учетные роли.
8. В **отдельной** ветке подготовить переключение всех клиентских SDK и форм авторизации на новый API: пересмотреть regex допускающий только `*.supabase.co`, `auth-config.js`, ключи, CSP, локальный ключ кэшированной сессии, OAuth/OTP redirect URLs, функции, экспорт результатов.
9. Проверить вход и сохранение обследования на синтетическом аккаунте (компьютер, мобильный интернет РФ без VPN, Mail.ru/Яндекс/Gmail, MFA), сравнить весь реестр и RLS-права.
10. Перед переключением временно остановить новые записи или назначить короткое окно обслуживания. Сделать **последний** свежий дамп, восстановить в новой базе, сверить контрольную SQL-проверку, переключить DNS/клиент и проверить повторный вход. Токены старого Supabase могут стать недействительными – это не удаляет пользователей.
11. Оставить старую систему в режиме резервного возврата до успешного подтверждения. После периода проверки обеспечить завершение переноса с учетом правовых требований и срока хранения зарубежных копий.

## Приемка
- Ни одна ранее существовавшая учетная запись, запись результатов и черновик не потеряна.
- Все UUID, связи user_id и права (owner/shadow/moderator) совпадают.
- Результаты открываются/редактируются/сохраняются только владельцем. RLS проверена с разными тестовыми аккаунтами.
- Коды входа доходят до Mail.ru, Яндекс и Gmail, либо точно диагностируется причина доставки; никаких гарантий 100% доставляемости.
- Вход, выход, MFA, профиль, избранное, подписки и Edge Functions проверены из России без VPN.
- В браузерной вкладке Network для чувствительных операций нет обращений к прежнему Supabase.
- Имеются зашифрованные резервные копии и успешный тест восстановления.
